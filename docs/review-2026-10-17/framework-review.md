# Targeted framework review — 17 October 2026

## Scope and preserved behavior

I kept Automation Exercise, Java 17, Selenium, Cucumber, TestNG, Maven, the page objects, all Gherkin scenarios and the eight browser component checks. No business assertion, advertisement interaction, test-data expectation, retry policy or scenario cleanup rule was changed. [preservation-check.json](preservation-check.json) records the unchanged historical report blobs and the checked source areas.

## Findings and changes

| Area                      | Review finding / targeted change                                                                                                                                                                                                                                                                                                                    |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Result categories         | Extent correctly reports Cucumber only. Added a TestNG listener that separately counts live, component and other test-method results, plus configuration failures/skips. Totals come from result sets, not suite constants.                                                                                                                         |
| Failure accounting        | A completed failing CI run verifies that the summary can report 30 live failures, eight skipped components and separate failed/skipped setup invocations. Surefire can include configuration invocations in its headline count; these are not relabeled as additional business scenarios.                                                           |
| Runtime paths             | Runner plugins, Extent, screenshots and Logback now write beneath ignored target/test-output/. Surefire remains under target/surefire-reports/. The frozen published reports are not a runtime output path.                                                                                                                                         |
| Stale evidence            | Execution start clears only known prior Cucumber/summary files in the runtime directory. An actual component-only invocation produced eight component passes, zero Cucumber cases and no old Cucumber/Extent HTML. Use mvn clean test for a completely fresh Surefire directory; mvn test may retain older class XML files, as Maven normally does. |
| Driver startup            | If timeout configuration throws after browser creation, the driver is now closed and the ThreadLocal removed before the original setup exception is rethrown. Cleanup exceptions are attached as suppressed errors.                                                                                                                                 |
| Driver isolation          | One ThreadLocal session per scenario thread is preserved. Component tests use their own before/after method lifecycle. No static customer or shared browser was added.                                                                                                                                                                              |
| Driver diagnostics        | A unique WARNING-level ChromeDriver log per local session captures startup issues without INFO command payloads that could log typed values. Diagnostics are runtime artifacts, not Git evidence.                                                                                                                                                   |
| Parallel reporting        | Existing UUID-keyed concurrent Extent mappings and atomic counters are retained. Different scenarios have separate Extent nodes; flushing remains at run completion. The new listener reads TestNG results after execution.                                                                                                                         |
| Screenshots and cleanup   | Hook ordering remains 200: capture evidence, 100: delete only the created account, 0: capture an uncaptured cleanup failure and quit in finally. Screenshot/cleanup exceptions remain failures. Actual E2E evidence is still attached to the Cucumber and Extent reports.                                                                           |
| Discovery and exit status | Surefire still includes RunCucumberTest and AdvertisementTest. Both runner providers remain, with exactly one supplying scenarios. No testFailureIgnore, hidden retry, continue-on-error, or swallowed Maven failure was introduced.                                                                                                                |
| CI environment            | The Chrome-only probe identified a missing usable sandbox, then incorrect permissions on the root-owned packaged helper. CI uses that installed helper with the required 4755 permissions on Ubuntu 24.04. No no-sandbox flag, site security bypass or global AppArmor disable is used.                                                             |
| CI evidence               | Java/Maven/Chrome versions, startup diagnostics, category validation and a generated GitHub job-summary table supplement the unchanged Maven failure status. Artifact upload runs even after failure and collects actual runtime output rather than historical snapshots.                                                                           |
